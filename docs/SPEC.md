## 1. 目的

パラデータ（フレーズごとに分かれた wav、または曲頭から書き出した全長のステム）から bmson 譜面を作るまでの作業を、1つのツールで完結させる。

1. 音切り（切断点の設定）を SliceX のように自動検出し、手作業は修正だけにする
2. BmsONE の不満点（ノーツ配置の操作性、BGA/BGI の設定、ノーツに ID がないことによる編集の難しさ）を解消した譜面エディタを作る
3. 外部プレーヤー（Pulsus）で任意の小節からプレビューできるようにする
4. bmson と MIDI（切断点）を出力する

## 2. 用語

| 用語 | 意味 |
|---|---|
| pulse (y) | bmson の時間単位。`resolution`（既定 240）pulse = 4分音符1つ |
| フレーズ素材 (Asset) | ユーザーが用意する wav 1ファイル。パラデータの1フレーズ |
| 配置 (Placement) | フレーズ素材を曲中のある pulse から鳴らすこと。同じ素材を複数回配置できる |
| 切断点 (CutPoint) | 配置内で音を切る位置。bmson の Note の y に対応する |
| スライス | 切断点から次の切断点までの音。bmson ではプレーヤーが再生時に切り出す |
| レーン割当 | スライスをどのレーン（x）で鳴らすか。未割当＝BGM（x = 0） |
| ノーツ | 「スライス × レーン」の組。LN の場合は長さを持つ |

## 3. スコープ

- 対応プラットフォーム: Windows のみ
- 譜面モード: `beat-7k`
- フレーズ素材の取り込みと配置

- BGA/BGI 設定、メタ情報編集
- Pulsus による小節指定プレビュー

## 4. bmson と本ツールの関係（設計の前提）

bmson の仕様から、ツールの設計を決める性質を整理する。

1. **ノーツ＝切断点**。bmson は再生時にプレーヤーがステムを切り分ける形式で、サウンドチャンネル内の全ノーツの y が切断点になる。wav を物理的に分割する必要はない。
2. **c = false で頭から再生し直す**。フレーズ素材の「配置」は、その配置の先頭 pulse に c = false のノーツを1つ置くことで表す。配置内の残りの切断点は c = true にする。
   - 配置の先頭に音の立ち上がりがなくても、先頭ノーツ（BGM ノーツになることが多い）は必ず出力する。
3. **ノーツの y を動かすと、音の切れ目が動く**。y の移動は「鳴るタイミングの変更」ではなく「スライスの変更」になる。BmsONE で配置操作が分かりにくい原因はここにあると考えられる。本ツールでは「レーン割当（x の変更）」と「切断点の編集（y の変更）」を別モードの操作に分ける（§6.4）。
4. **同じスライスを複数のレーンに割り当てられる**（同じ y・同じチャンネルで x だけ違うノーツ）。同じスライスを BGM とプレイアブルの両方に割り当てると BGM ノーツは捨てられるので、ツール側で「割当あり＝BGM ノーツは出力しない」に統一する。
5. **同じ配置の中で c が混在する y は c = false 扱いになる**。ツールが同じ y の c を常に揃えて出力する。
6. **同じ素材の配置が時間的に重なるとき**は、同じチャンネルに置くと先行する配置が切られる。重なる配置は別の SoundChannel に分けて出力する（仕様上、複数のチャンネルが同じファイルを参照してよい）。
7. **異なるチャンネルの同じ (x, y) のノーツは1つのノーツに融合される**（レイヤーノーツ）。長さが違うとエラーなので、検証対象にする。
8. **仕様書内の解釈差（要検証）**。仕様のスライス例の表では、c = false の後もオーディオ時間が連続しているように読める。一方、本文と図は「頭から再生し直す」と説明している。本ツールは「c = false でファイルの先頭から再生し直す」と解釈し、Pulsus の `--render` で実際の挙動を確認するテストを用意する（§11.4）。

### 4.1 完成品の例から分かった前提（v0.5 で追加）

`appendix/完成品の例` の bmson（ユーザーの過去作）の構造を調べた結果。

| 観察 | 本ツールへの反映 |
|---|---|
| 素材は曲頭から書き出した全長のステム（1本＝曲の長さ）。各チャンネルの c = false は y = 0 の1つだけ | 全長ステムは「pulse 0 に1回だけ配置したフレーズ」として扱う。フレーズごとの wav と同じモデルで両方に対応する。全長ステムを取り込むときは配置を自動で pulse 0 に置く |
| `resolution` が 96 | resolution は 240 固定にしない。読み込んだ値を保持し、新規作成時の既定値だけ 240 にする |
| `name` は `xxx.wav` だが、実ファイルは `xxx.ogg` | bmson 仕様の「拡張子を外して wav / ogg / m4a を探す」ルールを素材の解決に実装する。存在確認（V04）もこのルールで行う |
| `mode_hint` は `beat-7k` なのに、x が 9〜24 のノーツが全体の約7割ある | 9 以上の x は、譜面上の「BGM 列」として整理に使われている。プレーヤーでは BGM として鳴る想定。本ツールでは「BGM 列 n」として保持し、読み込み→書き出しで x を変えない（§6.4） |
| `l` は全ノーツに出力（すべて 0）、`lines` は y = 0 を含む、`bpm_events` に y = 0 の重複あり、`subartists` が `[""]` | 読み込みでは許容する。書き出しの形は既存ツールに合わせて、`l` は常に出力する |
| BGA は mp4 の動画1本を `bga_events` で1回表示 | BGA の素材に mp4 も許可する（仕様の推奨は webm だが、実際に使われている） |

- **要確認**: x が 9 以上のノーツを、各プレーヤー（Pulsus、beatoraja など）が実際に BGM として鳴らすか。§11.4 の null テストで確認する

## 5. 全体ワークフロー

```
[フレーズwav群] → ①取り込み → ②配置（曲中の位置を決める）
   → ③自動音切り（感度・クオンタイズ） → ④手動修正＋試聴
   → ⑤レーン割当（譜面作成） → ⑥BPM/STOP/小節線/BGA/メタ情報
   → ⑦検証 → ⑧Pulsusでプレビュー → (④〜⑧を繰り返す) → ⑨bmson / MIDI 出力
```

## 6. 機能要件

### 6.1 プロジェクトとファイル構成

- 正となるデータは bmson ファイル。単体でプレーヤーに読み込める状態を常に保つ。
- 編集用の補助情報はサイドカーファイル `<name>.ibs.json` に保存する。
  - 保存する内容: ノーツ/切断点/配置の安定 ID、配置と素材の対応、検出パラメータ、自動/手動の区別、色・メモ、表示状態
  - 理由: bmson にはノーツの ID がなく、未知フィールドを埋め込むと厳格なパーサを持つプレーヤーで読めなくなるおそれがあるため
- サイドカーがない bmson（他のツールで作ったものなど）も開ける。そのときは「SoundChannel → 素材」「c = false ノーツ → 配置の先頭」「それ以外 → 切断点」と復元し、ID は新しく振り直す。
- 素材のパスは bmson からの相対パスで保存する。絶対パス、`..`、NUL 文字は保存時にエラーにする。

### 6.2 フレーズ素材の取り込みと配置

- wav（PCM 16/24bit、32bit float、44.1/48kHz、モノラル/ステレオ）を取り込む。ogg は読み込みのみ。mp3 は警告（先頭に無音が入って位置がずれるため）。
- アレンジャービュー（DAW のような横軸タイムライン）で、素材をブロックとして配置する。
  - ドラッグで配置、グリッドにスナップ、複製、削除
  - 同じ素材の複数配置を可視化（色を共通にする）
- 配置位置は手動のドラッグで決める。数値入力（小節・拍・pulse）でも指定できるようにする。
- 配置の先頭が pulse グリッドに乗らない場合（書き出し時のオフセットなど）は、丸め誤差（ms）を表示し、閾値を超えたら警告する。

### 6.3 音切り（Slicer）

**自動検出**
- オンセット検出関数: スペクトルフラックス（既定）、エネルギー（RMS 差分）、HFC から選ぶ
- ピーク抽出: 移動中央値＋オフセットの適応閾値
- パラメータ:
  - 感度（0〜1。閾値のオフセットに対応する）
  - 最小間隔（ms。連打の誤検出を防ぐ）
  - 無音ゲート（dBFS。これ未満の区間では検出しない）
  - プリロール（ms。切断点を立ち上がりより少し前に置く。既定 0）
- パラメータを変えるとリアルタイムで再検出し、波形の上に結果を表示する。手動で編集した切断点は再検出しても消さない。

**クオンタイズ**
- グリッド: 4, 8, 12, 16, 24, 32, 48, 64分 と任意の分割
- 強さ: 0〜100%、または「許容幅 ±n ms 以内のものだけスナップ」
- **アタック欠けの警告**: スナップ先が検出した立ち上がりより後ろにずれると、アタックが前のスライスに入ってしまう。後ろ方向のずれが閾値（既定 3ms）を超えた切断点は赤く表示する。

**手動編集**
- 追加（クリック）、削除、移動（ドラッグ。グリッドスナップは Shift で ON/OFF）、範囲選択して一括削除・一括クオンタイズ
- 自動検出の点と手動の点は色で区別する

**試聴**
- スライスをクリックすると、そのスライスだけを再生する
- キーボードで前後のスライスへ移動しながら連続して試聴できる
- 配置全体の再生、ソロ/ミュート

### 6.4 譜面編集（Chart Editor）

BmsONE への不満を受けた中心機能。

**2つの編集モード**
- **割当モード（既定）**: 切断点の時間（y）を固定し、レーン（x）だけを変える。音が変わってしまう事故が起きない。
  - スライスを選んで数字キー `1`〜`7` でレーンに割当、`S` でスクラッチ、`0` で BGM に戻す
  - 上下キーで「次の切断点」へ移動（グリッドではなく切断点単位で動く）。タイピング感覚で譜面を打てる
  - ドラッグは横方向にだけ動く
- **切断点モード**: §6.3 と同じ操作を譜面ビュー上で行う。y が変わる操作はこのモードでしかできない。

**選択と編集**
- 矩形選択、時間範囲選択、素材/配置/レーンでのフィルタ選択
- コピー＆ペースト: 「割当パターン」を別の範囲に貼り付ける。相対 pulse が同じ切断点に割当を写し、対応する切断点がない場合は警告する
- 変形: ミラー、レーン入れ替え、ランダム（シード指定）
- LN: 割当後にドラッグで長さを設定。同じレーンのノーツと重なるとエラー表示
- Undo/Redo: すべての操作を対象にする

**表示**
- レーン表示（モード定義データから生成。§8.3）
- BGM 列: x = 0 に加えて、モードのレーン範囲外の x（beat-7k なら 9 以上）を「BGM 列」として並べて表示する。スライスを BGM 列に置くと、その x のまま出力する。列の数は譜面に合わせて増やせる。BGM 列はまとめて折りたたみ可能
- ノーツの色を素材ごとに変える / レイヤーノーツを示すマーク
- 縦スクロールの譜面ビューと横スクロールの波形ビューを並べて表示し、カーソルを同期する
- 密度グラフ（小節ごとのノーツ数）、総ノーツ数、`total` の推奨値

**タイミング**
- `init_bpm`、BPM 変化（ソフラン）、STOP
- 拍子: 小節ごとに拍子（例: 4/4, 7/8, 5/4）を指定する拍子トラックを持ち、そこから `lines` を生成する。手動での小節線の追加・削除も可
- 小節番号の基準は拍子トラック。プレビューの小節番号（§6.7）や数値入力もこれに従う

**BPM を変えたときの切断点（決定事項）**
- 切断点は **pulse で保持する**。BPM を変えても譜面上の位置（拍）は変わらない。
- ただし音声ファイルは書き出し時のテンポで鳴るため、配置済みフレーズの区間の BPM を変えると、切断点と音の立ち上がりがずれる。そこで次のように扱う。
  - BPM・STOP を変更した区間にかかる配置を検出し、「テンポ変更の影響あり」として警告表示する（V12）
  - 影響を受けた配置に対して「再検出」「そのまま」を選べる操作を用意する
- 運用上の前提: ソフランや STOP を含む区間のフレーズは、DAW 側でも同じテンポマップで書き出す。DAW と IBS のテンポマップを一致させる手段として、テンポマップの MIDI 書き出し（§6.8）を使う

### 6.5 BGA / BGI

- `bga_header` の管理（id とファイル。png/webm）。サムネイル表示
- 譜面ビューに BGA / LAYER / POOR の3レーンを持ち、イベントを配置する
- `back_image`、`eyecatch_image`、`banner_image`（15:4 の推奨サイズを検証）、`title_image`、`preview_music` をメタ情報画面で設定する

### 6.6 メタ情報

`title`、`subtitle`、`artist`、`subartists`（`key:value` を表形式で入力）、`genre`、`mode_hint`、`chart_name`、`level`、`judge_rank`、`total`、`resolution`

### 6.7 プレビュー

**内蔵プレビュー**（試聴用。判定などはなし）
- bmson の解釈どおりに切ったスライスを、カーソル位置から再生する
- 再生位置を譜面ビューと波形ビューに表示する

**外部プレーヤー（Pulsus）**
- 起動コマンド: `Pulsus.exe <bmson> -p -m <小節番号 0-999>`
- 小節番号は、カーソルの y と `lines` から求める
- 未保存の変更がある場合は、同じフォルダに一時ファイル（`.~preview_<name>.bmson`）を書き出して渡す。相対パスの素材が解決できるよう、同じフォルダに置く
- 起動コマンドは設定でテンプレートにする（例: `"{exe}" "{file}" -p -m {measure}`。使える置換子は `{file}` `{measure}` `{pulse}` `{seconds}`）。将来 beatoraja などに差し替えられるようにする
- 注意: Pulsus の bmson 対応は README 上「完全ではない」とされている。LN、STOP、BGA が動くかを開発初期に確認する
- 注意: Pulsus は GPL-2.0 のため、外部プロセスとして呼び出すだけにし、コードをリンク・流用しない

### 6.8 入出力

**bmson 出力**
- `version: "1.0.0"`、ノーツは y 順、§4 のルール（配置先頭の c = false、同じ y の c の統一、重なる配置のチャンネル分割、割当ありスライスの BGM ノーツを省略）を適用する
- 出力前に検証（§10）を行い、エラーがあれば出力しない（警告は出力する）

**MIDI 出力（切断点）**
- 用途: 他ツール（プナイプナイえんそう など）への切断点の受け渡し
- 出力の形式は「プロファイル」として切り替える。プロファイルは `midi_profiles/*.json` のデータで定義し、受け渡し先が増えてもコードを変えずに済むようにする

**プロファイル「プナイプナイえんそう互換」（既定）**

実際に読み込めた MIDI（`appendix/プナイプナイえんそう/d_bongo.mid`）の構造に合わせる。

| 項目 | サンプルの構造 | 本ツールの出力 |
|---|---|---|
| SMF 形式 | Type 1 | Type 1 |
| PPQ | 128 | `resolution` と同じ（既定 240。128 以外も読み込めることを確認済み） |
| トラック構成 | 指揮者トラックなし。1トラック＝1音素材 | 素材ごとに1トラック。指揮者トラックは作らない |
| トラック名 | 音素材の名前 | 素材のファイル名（拡張子なし） |
| テンポ | 各トラックの先頭に Set Tempo | BPM 変化をすべて各トラックに複製して入れる |
| 拍子 | なし | 入れない（変拍子でも出力しない） |
| チャンネル | ch1 | ch1 |
| ノート番号 | トラック内で1種類に固定 | 固定ピッチ（既定 60。設定で変更可） |
| ノートの長さ | 次のノートの開始まで（隙間なし） | 次の切断点まで |
| ベロシティ | ノートごとに値あり | 固定（既定 100）。意味を持つかは不明なため |
| 時間の基準 | 曲頭からの絶対位置 | 曲頭からの絶対位置 |

- **PPQ**: 既定は `resolution` と同じ値にして、丸め誤差をなくす。設定で 128 などの小さい値にした場合は、丸めが発生した切断点の数を集計して警告する（V14）
- **時間の基準**: 既定は「曲頭基準」（曲全体を1ファイルに出力し、曲頭を 0 tick とする）。受け渡し先では曲頭から書き出した wav を主に使うため
  - オプションとして「配置先頭基準」（配置ごとに1ファイルを出力し、その配置の先頭を 0 tick とする）も残す

**プロファイル「汎用」**
- SMF Type 1、PPQ = `resolution`（変更可）、指揮者トラックに Set Tempo と Time Signature を入れる
- STOP はマーカーイベントで位置を残す

**共通**
- STOP は MIDI で表現できないため、出力時に警告する（V13）
- 出力単位: 曲全体 / 選択した配置のみ
- テンポマップだけの MIDI も出力できる（DAW にテンポを戻す用途。§6.4。汎用プロファイルで出力する）
- テスト: サンプルの MIDI はユーザーの作品なのでリポジトリに入れない。同じ構造をもつ合成データでゴールデンテストを作る

**取り込み**
- bmson（§6.1）、wav/ogg

### 6.9 設定

プレーヤーの実行パス、コマンドテンプレート、オーディオデバイス、既定のグリッド・検出パラメータ、キー割当、テーマ

### 7.2 技術選定

| 項目 | 選定 | 理由 |
|---|---|---|
| 言語 | C++20 | DSP の速度、Qt との親和性 |
| GUI | Qt 6 Widgets（波形と譜面は自前で描画する QWidget） | 大量のノーツでも、描画範囲だけ描けば速い。QGraphicsView は要素数が多いと重い |
| ビルド | CMake | Core / CLI / GUI を別ターゲットに分けやすい |
| JSON | nlohmann/json (MIT) | Core を Qt に依存させないため |
| 音声デコード・再生 | miniaudio (Public Domain / MIT-0) | 低遅延のミキシング再生、wav/flac のデコード。ogg は stb_vorbis |
| FFT | pocketfft (BSD) | ヘッダのみで軽い。aubio は GPL なので避ける |
| テスト | GoogleTest (BSD) | Core のテストを Qt なしで回せる |
| CLI 引数解析 | CLI11 (BSD-3-Clause) | ヘッダのみ。サブコマンドとヘルプ生成が揃っている |

### 7.3 OSS 公開に関するルール

- 依存ライブラリは、OSS として配布できるものに限る（上表はすべて MIT / BSD / Public Domain 系。Qt は LGPL で動的リンクし、Qt の DLL を差し替えられる形で配布する）
- 本体のライセンスは **MIT**。上表の依存ライブラリはすべて MIT と両立する
- 公開先は **GitHub**。CI は GitHub Actions（Windows ランナー）で回す
- 外部プレーヤー（Pulsus。GPL-2.0）はプロセス呼び出しだけにし、リンク・同梱はしない
- BmsONE は挙動と UI だけを参考にし、コードは流用しない
- リポジトリに入れるテスト用音源・画像はすべて自作または自由ライセンスのものにする
- アイコンや UI の画像は自作のオリジナルにする。名称の由来は趣味だが、ゲームの公式キャラクター画像やロゴなど他者の著作物はリポジトリにも配布物にも含めない

### 7.4 性能目標

- 1フレーズ（30秒、48kHz、ステレオ）の切断点検出: 200ms 以内
- 素材 100 本、ノーツ 1 万個の譜面でスクロールが 60fps
- スライス試聴の遅延: 30ms 以内

## 8. アーキテクチャ

### 8.1 レイヤーと依存方向

```
          ┌──────────┐   ┌──────────┐
          │  gui (V) │   │   cli    │
          └────┬─────┘   └────┬─────┘
               │ 依存          │
          ┌────▼──────────────▼────┐
          │      app (C)            │  ユースケース、コマンド(Undo)、ドキュメント管理
          └────┬───────────────────┘
               │
          ┌────▼───────────────────┐        ┌──────────────────────┐
          │      core (M)           │◄───────│ infra (アダプタ)       │
          │ domain / services /     │ 実装    │ bmson JSON, サイドカー, │
          │ ports(インタフェース)     │        │ MIDI, miniaudio, 外部起動│
          └────────────────────────┘        └──────────────────────┘
```

- **core**: 標準 C++ だけで書く。Qt にもファイル形式にも依存しない。外部とのやりとりは `ports`（インタフェース）を通す
- **infra**: ports の実装（`BmsonRepository`、`SidecarRepository`、`MidiWriter`、`AudioDecoder`、`AudioOutput`、`PlayerLauncher`）
- **app**: Controller。ユースケースを Command として実装し、Undo スタックを持つ。GUI と CLI はどちらもここを呼ぶ
- **gui**: View。ViewModel 経由で表示し、ロジックは持たない
- **cli**: app のユースケースを引数から呼ぶ

### 8.2 ドメインモデル（core/domain）

```
Project
 ├ SongInfo            メタ情報
 ├ KeyMode             モード定義（レーン一覧）
 ├ TimingMap           init_bpm, BpmEvent[], StopEvent[], BarLine[], resolution
 │                     pulse ⇔ 秒 の変換を持つ
 ├ Asset[]             id, 相対パス, サンプルレート, 長さ
 ├ Placement[]         id, assetId, startPulse
 ├ CutPoint[]          id, placementId, pulse(配置内の相対), origin(auto/manual),
 │                     detectedOnsetSec(参考値)
 ├ Note[]              id, cutPointId, lane(x), length
 └ BgaTrack            header[], bgaEvents[], layerEvents[], poorEvents[]
```

- Note は「どの切断点を、どのレーンで鳴らすか」で、y を自分では持たない。そのため、割当モードでは仕組み上 y が変わらない
- Note の lane は bmson の x をそのまま持つ（0 = BGM、モード範囲内 = プレイアブル、範囲外 = BGM 列）。プレイアブルかどうかは KeyMode が判定する
- bmson の SoundChannel は、出力時に Placement から組み立てる（§4-6 の分割規則）

### 8.3 モード定義（拡張点）

レーンは `modes/*.json` のデータで定義し、コードに直接書かない。

```json
{ "mode_hint": "beat-7k",
  "lanes": [
    {"x": 8, "label": "SC", "kind": "scratch", "width": 2},
    {"x": 1, "label": "1", "kind": "white"}, {"x": 2, "label": "2", "kind": "black"}
  ] }
```

MVP では `beat-7k.json` だけを同梱する。任意の譜面フォーマットに対応するときは、出力側の `ChartExporter` ポートを追加する。

## 9. CLI 設計（将来実装。Core API はこの形で作る）

```
igusa slice   <wav> --bpm 175 [--sensitivity 0.6] [--min-interval 30] [--grid 16] [--out cuts.json]
igusa build   <project.ibs.json> --out song.bmson
igusa midi    <song.bmson> --out cuts.mid [--pitch 60] [--ppq 480] [--tempo-only]
igusa validate <song.bmson> [--json]
igusa info    <song.bmson> [--json]
igusa preview <song.bmson> --measure 12
```

- `--json` で、結果を標準出力に JSON で返す（他のツールから扱いやすくするため）
- 終了コード: 0 = 成功、1 = 検証エラー、2 = 引数エラー、3 = 入出力エラー
- GUI 実行ファイルとは別に `igusa-cli.exe` を作る（Windows の GUI サブシステムでは標準出力が扱いにくいため）

## 11. テスト方針

### 11.1 構成

```
tests/
 ├ specs/                 ← テスト仕様（markdown）。人が読んで検証内容を理解するためのもの
 │   ├ core/timing.md
 │   ├ core/slicer.md
 │   ├ infra/bmson_export.md
 │   └ ...
 ├ unit/                  ← GoogleTest。specs の各項目 ID と対応する
 ├ golden/                ← 期待される bmson / MIDI の正解ファイル
 └ fixtures/              ← テスト用 wav（合成したクリック音など。著作物は入れない）
```

### 11.2 テスト仕様 markdown の書式

```markdown
# タイミング変換 (core/timing)

| ID | 前提 | 操作 | 期待結果 |
|---|---|---|---|
| TIM-001 | init_bpm=120, resolution=240 | pulse 240 を秒に変換 | 0.5 秒 |
| TIM-002 | y=240 に STOP 240pulse, bpm=60 | pulse 240 を秒に変換 | 1.0 秒（停止の開始時刻） |
| TIM-003 | y=240 に BPM と STOP が同時 | 停止時間を秒に変換 | 変更後の BPM で計算される |
```

テストコードの名前は ID と「何を保証するか」にする（例: `TEST(Timing, TIM002_NoteOnStopActivatesAtStopStart)`）。

### 11.3 レイヤーごとの方針

- core: 単体テスト（タイミング、検出、クオンタイズ、SoundChannel の組み立て規則、検証）
- infra: ゴールデンファイルとの比較（bmson / MIDI の出力）、往復テスト（読み込み → 書き出し → 一致）
- app: Command の実行と Undo で状態が元に戻ること
- gui: 手動テスト手順を `tests/specs/gui/*.md` にチェックリストとして書く

### 11.4 Pulsus による実地検証（null テスト）

1. フレーズ素材を配置どおりに単純にミックスした wav を作る（正解）
2. ツールが出力した bmson を `Pulsus.exe song.bmson --render out.wav` で書き出す
3. 2つの差分の RMS が閾値以下であることを確認する

§4-8 の解釈差の確認と、出力の回帰テストを兼ねる。
