# 譜面編集の操作と Undo (app)

- 対象: `assignLanes` / `clearAssignments` / `changeNoteLane` / `changeNoteLength` / `removeNotes` / `pastePattern` / `remapLanes` / `editTiming` / `keepCutTimes` / `acceptTempoDrift` / `songEndPulse`（`ChartCommands`）
- テストコード: `tests/unit/app/ChartCommandsTest.cpp`
- 根拠: SPEC.md §6.4（Undo/Redo はすべての操作を対象にする、BPM を変えたときの切断点）
- 共通の前提: 120 BPM・resolution 240、bass.wav を pulse 0 に配置し、0 / 240 / 480 / 960 に切断点

## 何を保証するか

画面の 1 回の操作（複数スライスへの割当、貼り付け、BPM の変更など）が、1 回の Undo で戻ること。
何も変わらない操作では Undo の履歴が増えないこと（「元に戻す」を押しても何も起きない、という紛らわしさを避ける）。
BPM・STOP の変更と「テンポ変更の影響あり」の印が同じ Undo 単位になること。

## テスト項目

| ID | 前提 | 操作 | 期待結果 |
|---|---|---|---|
| CMD-001 | 上記 | 240 と 480 をまとめてレーン 4 に割当 → 元に戻す | 2 つのノーツ（レーン 4）。Undo の名前は「レーン割当」。1 回で 2 つとも消える |
| CMD-002 | 240 にレーン 2 | 未割当の 480 だけを解除 / 240 と 480 を解除 | 0 個・履歴は増えない / 1 個・Undo の名前は「割当の解除」 |
| CMD-003 | 240 にレーン 2 のノーツ | 同じレーン・同じ長さに変える / レーン 6・長さ 240 に変える | 履歴は増えない / 変わり、最後の Undo の名前は「ロングノーツの長さ」 |
| CMD-004 | 240 のレーン 3 をコピー | 5000（切断点がない）に貼る / 480 に貼る | 「見つからない」1・履歴は増えない / 1 つ追加・Undo の名前は「割当の貼り付け」 |
| CMD-005 | 上記 | 480 から 60 BPM にする → 元に戻す | 配置がずれる配置として返り、印が付く。変更前のタイミング（120 BPM、変化なし）も返る → 印と BPM 変化が一緒に戻る |
| CMD-006 | CMD-005 の直後 | 「時間を保つ」→ 元に戻して「そのまま」 | 960 の切断点が 720 に動き、印が消える → 切断点は 960 のまま、印だけ消える |
| CMD-007 | 上記 | init_bpm を同じ 120 に「変更」/ 曲の終わり | 履歴は増えず、ずれる配置もない / 最後の切断点 960 + 4 小節（3840）= 4800 |
| CMD-008 | 240 の切断点にレーン 3、480 にレーン 4 | ロングノーツに切り替え → もう一度 / 480 のノーツをレーン 3 へ移し、間隔 240 で切り替え | 長さ 240（次の切断点まで）、Undo は「ロングノーツの切り替え」→ 0 に戻る / 入る長さがないので `std::invalid_argument` |
